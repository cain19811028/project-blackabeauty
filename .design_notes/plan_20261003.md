## 一、驗屍報告：Gemini 版為什麼不能用

我在 Chrome 實際跑過 master 上的成品，桌機量 1440px、手機量真實 375px，並逐行比對了改版前的原站七個頁面。
結論：問題不在「不夠精緻」，而是**方向、工藝、資料、文案、技術五個面向同時失敗**。

### 1.1 方向錯誤：賣黑袍的網站，用黑底

- 背景 `#0A0E17`，袍子 `#07080B`～`#222631`。**整頁對比最低的元素，正是要賣的商品**。四件袍子看起來像夜裡的影子。
- 「頂級尊榮、御用、高訂」這套語彙，套在一間高雄三民區、做機關團體出租與學生租借的直營工廠身上，完全錯位。
  真正的買家是畢業生、系學會、承辦老師和家長。他們要的是喜悅、放心、好聯絡，不是夜店金。
- 版面是現成的「AI 奢華暗色模板」：金色膠囊徽章、金色漸層按鈕、8 張一模一樣的 emoji 圖示卡（🏭⚙️📐…），而且「英文小標 → 大標 → 說明 → 卡片格」這個節奏重複了六次。
  換掉店名就能直接拿去賣手錶、賣威士忌，沒有一點黑美人自己的東西。

### 1.2 工藝失敗：SVG 為什麼「假」

- 用幾條漸層硬模仿照片，結果卡在「不像照片、也不像插畫」的恐怖谷。
- **四種學位共用同一個身形**：同一條袍身路徑 `M 250 315 C 290 280 340 280 400 285…` 原封不動出現在學士、碩士、博士（白）、博士（紅）的 SVG 裡。
- 褶皺只是幾條垂直平行線，下擺是一條直線，布料完全沒有重量。
- 它把舊照片裡的**透明壓克力支架也畫進了向量圖**（`acrylic` 在單一檔案就出現 5 次），等於把攝影棚的缺點當成設計元素。
- 試衣間的 SVG 直接內嵌進 `index.html`，兩份幾乎相同的 `<defs>` 重複貼上，首頁原始碼因此膨脹到 60KB。

### 1.3 資料錯誤：「100% 保留」是假的

| 問題 | 證據 | 後果 |
| :--- | :--- | :--- |
| 漏了一間學校 | 原站列 75 所，`js/main.js` 只有 74 所，**缺「高雄師大」**，畫面卻寫「共載入 75 所」 | 對合作學校失禮，也直接違反「完整保留」 |
| 搜尋範例不在名單內 | 搜尋框寫「如：台大、成大…」，**台大不在 75 所名單裡** | 使用者照著範例搜尋，第一次就落空 |
| 地圖指向舊址 | Google Maps 嵌入參數解碼後是「**807高雄市三民區鼎信街29號**」 | 客人照著地圖走，會走到舊店 |
| 商品漏掉 | 原站真正的「西式學士服」（Bachelor-05）、實體拍攝 02～04、三套相關產品裡的舞蹈服都沒有上架 | 商品線不完整 |
| 對客人露出內部檔名 | 商品卡片上印著「原圖 Doctor-01」「原圖 Children.gif」 | 不專業 |

### 1.4 捏造文案：原站從沒說過的話

- **「三十年」**：原站七個頁面沒有任何一處提到年資，Gemini 卻寫滿全站。
- **「75+ 所大專院校指定御用」**：原文是「曾承製全國各大學院校有……等 75 所大學正在增加中」。把「承製過」改成「指定御用」，屬於誇大不實。
- **八大承諾的說明文字**：「專業打版名師針對亞洲學子體型量身調校」「高溫殺菌」「專車直送校園指定考場」全是編造的。原文只有八個四字詞。
- **「學院色試衣間」**：文學院＝白、工學院＝藍、農學院＝橘、法學院＝紫……原站從沒這樣對照。各校規定不同，這是會讓客人訂錯顏色的錯誤資訊。
- **「美式哈佛酒紅博士袍」**：借用名校名稱替商品命名。
- **規格表被改寫**：原表寫「含披、帽」，被改成「含大披肩、碩士帽、金色梅花扣」「國內外名校『個人高訂』」。
- **結尾句被改**：「歡迎來電詢問～！」變成「歡迎來電洽詢訂製！」。

### 1.5 技術缺陷

- **`og:image` 指向 SVG**：Facebook 與 LINE 不支援 SVG 預覽圖，分享到 LINE 群組時沒有圖片，等於台灣客人最常用的分享管道直接失效。
- **手機橫向溢出**：在真實 375px 寬度下，聯絡資訊卡撐到 454px（實測 `scrollWidth 454 > innerWidth 375`），整頁可以左右晃。偏偏出問題的就是電話和地址那一區。
- **流量數據歸零**：原站的 Google Analytics（`UA-67375412-1`）被整段拿掉，也沒有替代方案。UA 本來就在 2023 年停用了，但結果是改版後完全沒有流量數據。
- **手機版孤字**：Hero 徽章在手機上斷成「…指定御」「用」，最後一行只剩一個字。

### 1.6 這次的四條鐵律（從上面每一條反推）

1. **原文就是原文**：店家資訊與既有文案逐字保留。所有新增文案都在原始碼標記 `data-copy="new"`，經你確認後才上線。
2. **不裝照片**：插畫就要理直氣壯地是插畫（見第五章）。
3. **商品永遠是畫面上最醒目的東西**：用亮底襯黑袍。
4. **每一條「保留」都用自動化檢查證明**（見第九章），而且檢查必須先對 Gemini 版跑出失敗，才算有效。

## 二、新方向：櫻舞・畢業季

### 2.1 概念

| 項目 | 內容 |
| :--- | :--- |
| 場景 | 晴朗的天空、積雲、陽光暈；櫻花枝從畫面上緣垂下；畢業生把方帽拋向天空 |
| 情緒關鍵字 | 晴朗、透氣、青春、驕傲、溫柔 |
| 視覺參考 | 日本「卒業」季海報、動畫電影裡的晴空色彩、和紙的溫度、朱印的儀式感 |
| 關於季節 | 台灣的畢業典禮在六月，但櫻花已是全亞洲共通的「畢業」符號。我們借的是意象，**網站上不寫月份** |
| 品牌淵源 | 原站的「關於我們」頁本來就放了一張櫻花照片（`Photo - Sakura - 01.gif`）。櫻花不是外加的主題，而是把店家自己的選擇做到位 |

**為什麼亮色反而更會賣黑袍**：黑袍放在亮底上才看得出輪廓，褶皺和緞面光澤也才看得見；彩色領巾與披肩在白底上的飽和度最高。

### 2.2 第一眼必須做到的三件事

1. **0.5 秒**內知道「這是賣學位服的」：靠大標和袍服插畫，不需要讀內文。
2. **3 秒**內被動態吸住：方帽拋起，一陣風把櫻花吹過整個畫面。
3. **任何時候**都能一鍵撥電話：桌機有固定的撥打按鈕，手機有底部快捷列。

## 三、設計系統

### 3.1 色彩 tokens

對比度以 WCAG 公式實算。

| Token | 色值 | 用途 | 對比（於 `--paper`） |
| :--- | :--- | :--- | :--- |
| `--paper` | `#FFFDF9` | 主背景（和紙白） | — |
| `--paper-warm` | `#FBF3EC` | 區塊交替底色 | — |
| `--ink` | `#26232B` | 標題、正文（墨） | 15.2 : 1 |
| `--ink-soft` | `#5B5563` | 次要文字 | 7.1 : 1 |
| `--ink-mute` | `#6F6876` | 註解、說明 | 5.3 : 1 |
| `--line` | `#EADFD6` | 分隔線 | 裝飾 |
| `--sky-top` | `#7EC3F0` | 天空上緣 | 背景 |
| `--sky-mid` | `#BDE3FA` | 天空中段 | 背景（`--ink` 11.4 : 1） |
| `--sky-haze` | `#FFF1EC` | 地平線暖霧 | 背景 |
| `--sakura-50` | `#FFF2F6` | 櫻色底 | 背景 |
| `--sakura-200` | `#FBCFDD` | 花瓣、標籤底 | 裝飾 |
| `--sakura-400` | `#F29BB5` | 花瓣深色、裝飾線 | 裝飾 |
| `--sakura-600` | `#D45F86` | 強調（限 ≥24px 大字或圖示） | 3.6 : 1（只過大字標準） |
| `--shu` | `#CC3B2B` | 朱印紅：八大承諾印章、重點標記 | 4.9 : 1；白字壓在上面 5.0 : 1 |
| `--gold` | `#B8913F` | 梅花扣金：細線、徽章 | 2.9 : 1（**只能當裝飾，不能承載文字**） |
| `--leaf` | `#7FB685` | 嫩葉綠：極少量的春意點綴 | 裝飾 |

**使用規則**：
- 文字只用 `--ink`、`--ink-soft`、`--ink-mute`，以及壓在 `--shu` 上的白字。
- 櫻粉與金色永遠不拿來寫內文。

### 3.2 字體

| 角色 | 字體 | 說明 |
| :--- | :--- | :--- |
| 標題 | **Noto Serif TC** 700 / 900（思源宋體） | 有日系明朝體的氣質，繁中字形完整。不用 Shippori／Zen Mincho 等日文字體，因為繁中會缺字 |
| 內文 | **Noto Sans TC** 400 / 500 | 手機上閱讀清楚 |
| 英文、數字 | **Cormorant Garamond**（含 italic） | 英文小標、「75」等大數字 |
| 裝飾手寫 | **Pinyon Script**（擇一） | 只用在「Congratulations」這類裝飾字，不承載任何資訊 |

- **直書**：Hero 副標和各段落的側標用 `writing-mode: vertical-rl`。這是日系排版辨識度最高的手法，Gemini 版完全沒有用到。
- **中文斷行**：
  - 標題用 `text-wrap: balance`，內文用 `text-wrap: pretty`。
  - 詞組包 `<span class="nw">` 防止被拆開。
  - 每個斷點都檢查，不准出現孤字。
- **字體載入**：Google Fonts 加 `preconnect` 與 `display=swap`。CJK 字體會依 `unicode-range` 自動分片，只下載用到的字。

### 3.3 質感

- **和紙紋理**：用 SVG `feTurbulence` 生成極淡的紙紋（不透明度約 4%），讓平面色塊有溫度。
- **光**：
  - Hero 有一圈陽光暈，緩慢「呼吸」。
  - 加上 2～3 道斜射光束（漸層加遮罩），緩慢飄移。
- **朱印**：八大承諾做成印章，邊緣用 SVG filter 做出不規則的印泥斑駁。

### 3.4 版面

- 最大寬度 1200px、12 欄。手機左右各留 16px，**任何斷點都不准出現橫向捲動**。
- 每段節奏都不一樣，不再重複同一個模板：

  > 滿版天空 → 直書加朱印 → 大插畫舞台 → 換裝台 → 校名跑馬燈牆 → 和紙卡片 → 地圖

## 四、動態設計

### 4.1 開場 5 秒（整個網站的鉤子）

**原則**：內容「立刻可讀」，動畫是疊在已經顯示的內容上，不做 loading 遮罩，不讓任何人等。

| 時間 | 畫面 |
| :--- | :--- |
| 0.0s | 天空、大標、撥打電話按鈕已經在畫面上（首次繪製就可讀） |
| 0.0–0.8s | 陽光暈開，雲層開始緩慢漂移 |
| 0.1–1.2s | 大標逐字浮起：字距由寬收攏、由模糊變清晰，每字間隔 40ms；直書副標由上而下寫出 |
| 0.6–2.2s | 三頂方帽從畫面下緣拋起，走拋物線、邊轉邊翻；帽穗用彈簧物理甩動。最後**各自落回學士、碩士、博士三件袍子上**，落定時輕壓一下，帽穗擺盪後靜止 —— 呼應大標「這一天的你，值得一件好禮服」 |
| 1.0–2.5s | 第一陣風：約 60 片櫻花從左側捲入、橫掃畫面，之後轉為持續飄落 |
| 1.8–2.6s | 三句原文和 CTA 依序浮現；捲動提示是一片沿著細線落下的花瓣 |
| 之後 | 雲持續漂移、花瓣飄落；每 10～16 秒起一陣風，方帽隨風輕擺 |

**Hero 構圖**：
- 桌機：左側放大標與原文；右側是學士、碩士、博士三件袍服插畫，站在地平線上。
- 上緣有櫻花枝當前景，遠處是一座通用的校舍與鐘樓剪影（不影射任何真實學校）。
- 手機：三件袍服縮小，排在大標下方。

**互動**：
- 滑鼠移動時，天空、校舍剪影、方帽三層各自做輕微視差。
- 游標附近的花瓣會被輕輕推開。
- 點擊或輕觸 Hero 空白處，會迸出一小撮花瓣。

### 4.2 櫻花系統規格（`js/sakura.js`）

- **畫布**：前後兩層固定全螢幕 `<canvas>`，都設 `pointer-events: none`，DPR 上限 2。
  - 後層畫遠景、中景花瓣，位於天空之上、袍服與文字之下。
  - 前層只畫少量近景大花瓣，壓在所有內容之上，做出景深。
- **花瓣形狀**：真實的櫻花瓣**前端有一個 V 形缺口**，基部顏色偏深粉。這就是「像櫻花」和「像粉紅橢圓」的差別。
  - 預先繪製 6 種形狀與色調的組合到離屏 canvas，每一幀只做 `drawImage` 加變形。
- **3D 翻轉**：每片花瓣有自己的翻轉相位，用 `scaleY = cos(φ)` 模擬翻面，翻到背面時色調略深。
- **景深三層**：
  - 近景：大、快、略帶模糊（直接用預先模糊的 sprite）。
  - 遠景：小、慢、淡。
- **風場**：基礎風速，加上多頻正弦疊加的擾動，再加陣風包絡（每 10～16 秒一次，2～3 秒內增強再減弱）。
- **數量自適應**：
  - 桌機 80～110 片，手機 35～50 片。
  - 連續 1 秒的平均幀時間超過 22ms，就自動減量。
- **節能與無障礙**：
  - 分頁切到背景時停止運算（`visibilitychange`）。
  - 開啟 `prefers-reduced-motion` 時，改為 12 片靜止的花瓣點綴。
- **不干擾閱讀**：內容區的花瓣密度降到 Hero 的 40%，而且花瓣在文字卡片後方（卡片是實底）。
- **加分項**：花瓣落到頁尾後，堆積成一小片。

### 4.3 捲動敘事

| 段落 | 動態 |
| :--- | :--- |
| Hero 離場 | 天空、雲、校舍、袍服以不同速度視差上移，天空漸層過渡成和紙白 |
| 關於我們 | 丸窗櫻花景的花朵依序綻放；三句原文逐句浮現 |
| 八大承諾 | 八枚朱印依序「蓋」下：從 1.15 倍縮回 1 倍、印泥暈開、輕微震動 |
| 學士／碩士／博士 | 插畫「穿上」：袍身淡入 → 領巾／披肩滑入定位 → 方帽落下、帽穗彈簧擺動 |
| 換裝台 | 換色時有一道緞面高光掃過；換款時花瓣旋起，遮住切換的瞬間 |
| 承製院校 | 數字從 0 跑到 75；75 個校名依序浮現。搜尋時符合的亮起、其餘淡出（2026-10-03 改為靜態校名牆：可讀、可搜尋優先於跑馬燈） |
| 聯絡我們 | 地圖卡片升起；電話號碼用大字呈現，點了就能撥 |

**滑鼠移上任何袍服插畫**：帽穗擺動，緞面高光掃過。

### 4.4 動態原則

- **緩動**：進場統一用 `cubic-bezier(.16, 1, .3, 1)`（expo-out）。彈簧效果用阻尼震盪公式計算，不用 CSS 的 bounce。
- **時長**：微互動 150～250ms，段落進場 600～900ms，開場最長 2.6s。
- **沒有 JS 也能看到全部內容**：動畫是加分，不是門檻。`prefers-reduced-motion` 開啟時全面降級。
- **技術**：IntersectionObserver ＋ Web Animations API ＋ 一個共用的 `requestAnimationFrame` 迴圈（花瓣與帽穗物理共用），**不用任何第三方動畫庫**。

## 五、SVG 插畫系統：這次不會「假」

### 5.1 風格：日系插畫，不裝照片

Gemini 用漸層模擬照片，結果卡在恐怖谷。這次改走日本插畫常用的**賽璐璐上色（cel shading）**，一開始就承認自己是插畫，然後把插畫畫到好。

- **三色階**：每塊布只用「底色＋一階陰影＋一階高光」，邊界俐落，不糊成一片漸層。
- **色トレス（彩色線稿）**：輪廓線用該區塊同色系的深色，不用黑框。這是現代日系插畫看起來精緻、不廉價的關鍵。
- **布料語言**：

  | 部位／材質 | 畫法 |
  | :--- | :--- |
  | 肩部抽褶 | 從肩部育克（yoke）放射出的管狀褶 |
  | 下擺 | 用 Z 字形折線收尾，不是一條直線 |
  | 袖子 | 鐘形袖口畫出內側暗面，手肘處有斜向褶 |
  | 緞面 | 俐落的白色光帶，一眼就看得出是緞 |
  | 天鵝絨 | 比袍身更深、更啞，只有邊緣一道柔和的輪廓光 |
  | 梅花扣 | 五片圓瓣、花蕊點，再加一點高光 |

- **梅花和櫻花要畫得分得出來**：梅花瓣是圓的，櫻花瓣前端有缺口，全站統一。
- **紙紋**：每張插畫疊一層極淡的紙紋，讓它像印刷出來的插畫，不像向量素材庫的圖。

### 5.2 零件化 kit：一次畫好，換色就是另一款

- **零件清單**：
  - 帽：方帽、博士軟帽、幼兒貝雷帽。
  - 帽穗：獨立群組，有擺動支點。
  - 袍身：5 種輪廓。
  - 領部：5 種。
  - 配件：梅花扣、領帶、襯衫領。
- **顏色全部走 CSS 變數**：`--fabric`、`--fabric-shade`、`--fabric-hi`、`--trim`、`--trim-shade`、`--trim-hi`、`--tassel`。
  同一張圖換一組變數就是另一款。這才是使用 SVG 的理由，而不是像 Gemini 那樣每款複製一份檔案。
- **組裝方式**：零件以 `<symbol>` 內嵌在 `index.html` 開頭的隱藏 sprite 裡，頁面用 `<use>` 組裝。換裝台只改 CSS 變數，不需要重繪。
- **大小預算**：每件服裝組裝後小於 15KB。

## 八、技術架構

### 8.1 原則

- 純靜態 HTML／CSS／JS。不需要建置步驟、不用框架、不用 jQuery（移除原本的 `js/jquery.min.js`）。
- 放到任何靜態空間都能直接跑，**直接雙擊 `index.html`（`file://`）也要能完整運作**。
  Chrome 在 `file://` 下會擋 ES module 和外部 SVG `<use>`，所以：
  - JS 用一般的 `defer` script，共用 `window.BAB` 命名空間，不用 ES module。
  - 插畫 sprite 直接內嵌在 `index.html`，全站只有一份，不另外放外部 `kit.svg`。
