## 一、現況診斷

對象是 v1（`949e058`）。在 Chrome 實測桌機 1440px 與手機 375px，並截圖逐段檢查。

**總評**：Hero 像一部電影，但往下捲就變回型錄。最該發光的學位服只在 Hero 出現一次。

| 區塊 | 問題 |
| :--- | :--- |
| Hero | 滑鼠視差位移只有 ±7～16px，幾乎感覺不到。三件袍子平面排成一列，接地陰影是一塊扁平橢圓，沒有站在空間裡的感覺。「三十年」印章壓在學士服上，像一張貼紙。左側直書的公司名落在雲裡，看不清楚 |

## 二、方向

| 關鍵字 | 意思 |
| :--- | :--- |
| **景深** | 每個畫面都拆成前景、中景、遠景。捲動或移動滑鼠時，各層以不同速度移動 |
| **光** | 包括陽光暈、斜射光束、緞面反光、金扣閃光。光源統一在右上方，和現有的太陽同方向 |
| **穿越** | 段落之間不硬切，而是像鏡頭穿過雲層或花瓣，進到下一幕 |

- **時段**：全站維持早晨晴空的光（決策 2）。
- **立體的定義**：手繪 SVG 拆成多個圖層，再加上 CSS 透視與光影（決策 1）。不用照片，不用 3D 模型。

## 四、改善規劃

### 4.1 P0：效果最大，先做

**① Hero：多層景深加穿雲轉場**

- **分層**：拆成 8 層，依序是天空漸層 → 遠雲 → 校舍 → 近雲 → 袍服 → 方帽 → 前景櫻花枝 → 前層花瓣。
- **捲動**：鏡頭往前推。前景花枝快速移出畫面，雲層放大散開，袍服往上浮，最後穿過一片雲進入「關於我們」。
- **滑鼠**：視差加大到能明顯感覺，前景約 ±40px、遠景約 ±6px。整個舞台再隨滑鼠做 `perspective` 微傾。
- **光**：
  - 太陽暈加 3 道斜射光束（`mix-blend-mode: screen`），捲動時光束角度跟著轉。
  - 袍子底下改成柔和的接觸陰影，再加一點地面反光。
- **修正**：
  - 「三十年」印章移到標題旁，加上蓋印動畫。
  - 直書公司名改放到天空中比較乾淨、可讀的位置。

**② 學位服展廳（新段落）：全站高潮**

- **捲動**：釘住（sticky）一個舞台，往下捲時依序換場：學士 → 碩士 → 博士。
- **光色**：每換一款，背景的光帶改成該款領巾或披肩的顏色。仍是早晨的亮底，只換點綴色。
- **立體感**：
  - 把袍身、披肩或領巾、方帽、帽穗拆成獨立圖層。
  - 滑鼠移動時各層位移不同，整體再傾斜最多 8°。
  - 平面插畫拆層後，一傾斜就會看起來有厚度。
- **緞面反光**：一道高光以 `soft-light` 疊在布料上。桌機跟著游標移動，手機跟著捲動移動。梅花扣與金邊偶爾閃一下。
- **換裝台**：展廳的最後一幕。點色票 → 一道緞面光掃過 → 換色，同時花瓣旋起，遮住切換的瞬間（沿用 `plan_20261003.md` §4.3）。只列原照片裡實際有的顏色。

### 4.2 P1：撐起全站節奏

**③ 打破模板**

- **標題進場**：輪流使用 3～4 種，分別是遮罩揭露、直書由上往下寫、逐字由模糊收攏（Hero 已有）、大字描邊。
- **背景大字**：放超大、半透明的描邊宋體字，例如「學士・碩士・博士」，和前景反方向移動，填掉現在的大片空白。
- **過場**：段落之間用櫻花枝、雲層、和紙撕邊銜接，不再是平直的色塊交界。

**④ 卡片與朱印的光感**

- **服務三卡**：
  - 游標附近出現暖色柔光（不是霓虹光）。
  - 插畫分層並微微傾斜：衣架、泡泡、捲尺各自位移。
- **八枚朱印**：捲動時一枚一枚蓋下去，印泥暈開，紙面輕震。排列改成一張展開的和紙卷軸，取代漂浮的 4×2 格子。

### 4.3 P2：收尾

**⑤ 院校牆**

- 維持靜態、可讀（依 10-03 的決定）。
- 入場時校名做波浪式依序亮起，搜尋命中的校名會發光。
- 「75」這個數字加一道金屬光澤掃過。

**⑥ 聯絡我們與頁尾**

- 地圖外加和紙相框，並套用輕微的色調濾鏡，貼近整體色系。
- 頁尾做成最後一幕：花瓣堆積（原計劃 §4.2 的加分項）、Congratulations 手寫字、撥號按鈕。

### 4.4 暫緩

- **一天的光線**：整頁捲動等於畢業典禮的一天，從早晨、午後到黃昏（仍是亮色調）。技術上用一個 `--light-warmth` 變數，同時控制背景、光束與陰影色溫。依決策 2 暫緩。
- **方案 B／C 的立體**：見決策 1。若 A 的效果不夠，再回頭評估。

## 五、技術做法

| 項目 | 做法 | 理由 |
| :--- | :--- | :--- |
| 捲動驅動 | 擴充 `BAB.ticker`，每段算出 0～1 的進度。M1 起改成由 JS 直接寫入各圖層的 `transform`，每層的公式集中在 `motion.js` 的一張表裡 | 沿用現有的單一 rAF 迴圈，所有瀏覽器都能跑，不必引入 GSAP。原本規劃的「寫進 CSS 變數 `--p`」會讓整個 Hero 子樹每幀重算樣式，所以不採用 |
| 立體 | CSS `perspective` 加 SVG 分層 | 保住插畫風格與換色能力，手機也跑得動 |
| 光 | 用漸層加 `mix-blend-mode`；動畫只改 `transform`、`opacity` | 避免每一幀重繪。大面積的 `backdrop-filter` 和 SVG filter 不做動畫 |
| 插畫體積 | 依 `plan_20261003.md` §8.1，sprite 內嵌在頁面，全站只有一份（`file://` 會擋外部 `<use>`）。各款袍服由共用 `<symbol>` 零件，搭配 `tokens.css` 已有的 `.cw-*`、`.trim-*` 色系組成 | `index.html` 已有 119KB。零件共用之後，14 款袍服不會讓檔案線性膨脹 |
| 平滑捲動 | 桌機用 Lenis，鎖定版本，放在 `js/vendor/`，以一般 `defer` script 載入（`file://` 可用）。由 `BAB.ticker` 驅動它的 raf | **刻意偏離** `plan_20261003.md` §4.4「不用第三方動畫庫」：它只負責捲動慣性，所有動畫仍由自家 ticker 驅動 |
| 手機 | 圖層減半；沒有 hover，反光改由捲動連動；不用陀螺儀（iOS 需要授權） | 效能與體驗 |
| 降級 | `prefers-reduced-motion`：無視差、無傾斜、無慣性捲動，展廳改成一般直向排列。沒有 JS 時全部內容可見 | 原計劃鐵律 |

**效能預算**：沿用 `plan_20261003.md` §8.3，另外新增：

| 項目 | 上限 |
| :--- | :--- |
| Hero 同時移動的圖層 | 桌機 8 層、手機 4 層 |
| 捲動期間的長任務 | 不得出現超過 50ms 的任務 |
| 第三方 JS | 只有 Lenis 一支 |

## 六、刻意不做的事

- **不轉暗色**，不用霓虹紫藍漸層，也不讓毛玻璃到處都是。這些就是 Gemini 版的「AI 模板味」。
- **手機上不接管捲動**，也不強制水平滑動。
- **不新增未經確認的文案**。新文案一律標記 `data-copy="new"`，待審後才上線。

## 七、A／B 前後比對

**需求**：保留 v1（A 版）原貌，讓客戶能同時看到 A 版與改版後的 B 版。
**狀態**：2026-11-13 採用（決策 5），M0 已完成。

### 7.1 做法

**① 凍結 A 版**

- 在 `master` 的 `949e058` 打上 tag `v1-sakura`，作為不可變的快照。
- `master` 維持 A 版不動。B 版在 `feat/depth-and-light` 開發，客戶確認後才合併。

**② 比對頁由腳本產生，不在 repo 裡複製程式碼**

- 新增 `tools/build-compare.mjs`：
  - 用 `git archive v1-sakura` 匯出 A 版到 `dist/compare/a/`。
  - 把目前的工作目錄匯出成 B 版，放到 `dist/compare/b/`。
  - 加上 `dist/compare/index.html` 比對頁。
- `dist/` 加入 `.gitignore`。
- A 版永遠從 tag 取出，不可能被改壞。repo 裡也不會出現兩份程式碼，`check-content` 等工具不會掃到重複內容。
- 只匯出 `index.html` 和它載入的 `css/`、`js/`、`images/`。舊照片、`images/new/`、jQuery、`remove.js` 都不匯出。
- 匯出後逐一檢查頁面引用的本地檔案，缺任何一個就讓建置失敗，避免在客戶面前出現破圖。
- 兩版的 `index.html` 都會在 `</body>` 前注入一行 `bridge.js`。它只負責回報捲動位置，不畫任何東西。
  因為 `file://` 下的 iframe 彼此跨來源，同步只能靠 `postMessage`。

**③ 比對頁的呈現模式**

| 模式 | 內容 | 適合 |
| :--- | :--- | :--- |
| 手機並排 | 兩個 375×812 的框並排 | 最直覺。客戶多半用手機看，兩框也放得下 |
| 桌機切換 | 單一全尺寸畫面，按鈕、`A`／`B` 鍵或空白鍵切換 | 感受景深與光影。縮小之後就看不出效果 |
| 桌機並排 | 兩個 1440 寬的頁面縮成 50% 並排 | 看整體版面差異 |

- **段落按鈕**：兩邊同時捲到同一段。按鈕從兩版實際的段落自動產生，只有一版有的段落會標上「B 新增」或「A 才有」。
- **捲動同步**：最後被操作的那一版帶頭，另一版跟著捲。位置用「第幾段＋段內比例」換算，不用整頁比例：B 版多了展廳，頁長不同，按整頁比例會對不齊。
- **缺段提示**：帶頭的一版捲到另一版沒有的段落時，另一版蓋上「A 現行版／沒有「○○」這一段」的提示。
- **重播開場**：同時重新載入兩邊，讓兩版的開場動畫一起播。切換模式或改變視窗大小時也會重新載入，因為開場的拋帽軌跡是在載入時依畫面尺寸計算的。

**④ 展示方式**

- **當面展示**：雙擊 `dist/compare/index.html` 即可，不需要伺服器。
- **遠端展示**：不需要（決策 5）。日後若要遠端，把 `dist/compare/` 上傳到靜態空間並加上 `noindex` 即可，比對頁本身不必修改。

### 7.2 不採用的做法

| 做法 | 不採用的原因 |
| :--- | :--- |
| 在 repo 裡複製一份 `v1/` | 最簡單，但兩份程式碼共存：工具和搜尋會掃到重複內容，之後也容易不小心改到 A 版 |
| 只用 `git worktree` | 適合開發時自己對照，但客戶要開兩個資料夾，不適合交付 |
| 只給截圖或錄影 | 看不到互動。可以當備案，例如方便傳到 LINE 群組 |

### M0 比對基礎（2026-11-13 完成，待審）
